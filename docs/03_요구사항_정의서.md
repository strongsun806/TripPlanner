> 도메인 선정 근거 · 기획 검증 결과는 [`01_도메인_확정.md`](01_도메인_확정.md), Tool 명세는 [`02_Tool_정의서.md`](02_Tool_정의서.md),

## 1. 필수 기능 (F3001 ~ F3019)

| 번호 | 분류 | 요구사항명 | 이 서비스에서의 구현 | 위치 | 확인 |
|---|---|---|---|---|---|
| F3001 | Tool | Tool 명세 정의 및 등록 | 이름 · 설명(언제 부르는지) · 입력 JSON Schema · 함수를 `Tool` 로 등록. 외부 API 툴(3)과 로컬 서버 API 툴(3)을 `kind` 로 구분 | `tools.py`, `app/agent/registry.py`, `GET /api/tools` | `python tools.py` |
| F3002 | Tool | 후보 목록 Tool | `search_places` — Geoapify 로 여행지 반경 안의 관광 후보. 날짜를 안 주면 오늘로 조회하고 그 사실을 응답에 밝힘. `place_id` · 좌표를 다음 Tool 입력으로 넘김. 국내는 카카오 · TourAPI 로 보충 가능 | `tools.py` | S1, 4-1 캡처 |
| F3003 | Tool | 상세정보 Tool | `get_weather` — 좌표 · 날짜로 그날 강수확률 · 기온. 강수확률이 비면 0 으로 채우지 않고 `NO_FORECAST` 로 판단 보류. 예보 범위 밖은 `OUT_OF_RANGE` | `tools.py` | 4-1 캡처 |
| F3004 | Tool | 보조 정보 Tool | `search_nearby_food` — 카카오 로컬로 주변 식당 이름 · 주소 · 링크. 결과 없음은 `NO_DATA`. 식당과 일정 장소는 위치로만 묶고 영업 여부는 지어내지 않음 | `tools.py` | S1, S4 |
| F3005 | Agent | 요청 분석 | LLM 이 의도(6종)와 기준(날짜 · 시각) · 선호(지역 · 야외/실내) · 제약(끝나는 시각 · 야외만 · 날짜 고정) 조건을 추출. 못 뽑은 조건은 비워 두고, 해석한 내용은 `assumptions` 로 밝힘 | `app/agent/llm.py` `analyze` | S6, S7 |
| F3006 | Agent | 계획 수립 | 의도와 현재 전략으로 Tool 순서를 규칙으로 구성 · 보관(`steps`). 해외면 식당 Tool 제외, 인사 · 사용법은 계획 단계를 건너뜀 | `app/agent/graph.py` `plan` | S2, S5 |
| F3007 | Agent | Tool 호출 · 결과 전달 | 계획대로 호출, 앞 결과(좌표)를 다음 입력으로, 결과는 Tool 이름을 키로 보관. 실패해도 사유를 남기고 진행 | `graph.py` `execute` | S4 |
| F3008 | Agent | 제약 판단 | 강수확률 > 50% 면 야외 제외. 도보(분)=직선거리×1.3÷4km/h×60, 체류=(시간창−이동)÷장소수 ≥ 40분. 체류 · 영업시간은 지어내지 않고 '늦어도 언제 나서야 하는지' 역산해 제시 | `app/agent/judge.py` | S1, A1 |
| F3009 | Agent | 재계획 | 비 → 실내, 야외만이면 → 다음 날, 후보 없음 → 반경 확대, 동선 초과 → 반경 축소. 이미 받은 결과는 캐시로 재사용. 상한 3회에서 멈추고 조건 조정을 되물음. 키 누락처럼 다시 해도 같은 실패는 재계획 안 함 | `graph.py` `judge` | S2, S3 |
| F3010 | Agent | 대화 맥락 | 세션별로 확정 조건 · 직전 추천 요약 · 최근 3턴 요약만 보관 (Tool 원본 없음). 후속 요청은 바뀐 필드만 갱신 | `app/agent/memory.py` | S6 |
| F3011 | Agent | 최종 응답 | 추천 일정 · 날씨 · 식당 · 판단 기준(계산식) · 근거 Tool 결과 · 제외 사유 · 기본값/해석을 함께 제시. LLM 이 실패하면 확인된 사실로 규칙 기반 문장 | `graph.py` `respond`, 대화 화면 카드 | 화면 |
| F3012 | 로깅 | 이벤트 발행 | 단계 진입 · 종료, Tool 요청 · 응답 · 소요 시간, 의도 분류 · 계획 · 재계획 판단과 이유, LLM 호출을 세션 · 실행 식별자와 함께 발행. 발행자는 구독자를 모름 | `app/agent/events.py` | API 시험 |
| F3013 | 로깅 | 로깅 Agent | 버스 구독자로 붙어 받는 즉시 SQLite 에 순서대로 덧붙임. LLM 사용 안 함, 저장 실패해도 대화 정상 | `app/logging_agent.py` | S8 |
| F3014 | 로깅 | 실행 로그 관리 | 세션 목록 · 상세(실행 순서) · 삭제. 수정 API 없음 (PUT → 405) | `app/api/logs.py`, 실행 로그 화면 | API 시험 |
| F3015 | 계획 | 계획 저장 · 조회 | 장소 · 도시 · 날짜 · 시작/종료 · 좌표 · 생성 일시 저장. 같은 날 시간이 겹치면 저장하고 `overlaps` 로 알림. 대화 카드의 '이 일정 저장' | `app/api/plans.py` | API 시험 |
| F3016 | 계획 | 수정 · 삭제 | 내 일정 화면 시간표에서 블록을 눌러 수정 · 삭제, 목록에 바로 반영 | `frontend/plans.html` | 화면 |
| F3017 | 서비스 | FastAPI 백엔드 | `/api/chat` · `/api/plans` · `/api/logs` 를 다른 경로로, 요청 · 응답을 Pydantic 모델로 정의 | `app/main.py`, `app/schemas.py` | `/docs` 캡처 |
| F3018 | 서비스 | 화면 | HTML/CSS/JS 로 대화 · 내 일정 · 실행 로그 화면. 모두 백엔드 API 로 데이터 표시 | `frontend/` | 화면 |
| F3019 | 서비스 | 실행 과정 표시 | 답변과 함께 단계 · Tool 호출 · 판단을 실행 순서대로, 재계획 지점은 노랑 띠. 처리 중 표시, Tool 실패 배지, 키 누락 시 설정 안내 | `frontend/chat.html` | 화면 |

## 2. 심화 기능 (F3020 ~ F3023) — 네 가지 모두 수행

| 번호 | 요구사항명 | 구현 | 위치 | 확인 |
|---|---|---|---|---|
| F3020 | 로깅 Agent 평가 | 실행이 끝나면 규칙 넷(계획 밖 호출 · 같은 인자 반복 · 과도한 재계획 · 같은 Tool 연속 실패)으로 판정(LLM 없음). 근거 이벤트가 없으면 '판정 불가'. 이상일 때만 LLM 이 3문장 이내 진단, 판정과 다른 칸에 저장. 메인 Agent 는 직전 판정을 참조 | `app/evaluator.py` | A4, A5, 실행 로그 화면 |
| F3021 | Planner / Worker 분리 | Planner 가 고정 인자를 표시한 작업 목록을 만들고, Worker 는 평소 LLM 없이 수행. 결과 없음 · 대상 없음 · 잘못된 입력일 때만 LLM 이 재시도/건너뜀/계획 변경 요청을 판단 (같은 Tool, 2회, 고정 인자 불변). 해결 못 한 실패는 Planner 재계획에 반영, 로깅 Agent 규칙이 이상을 보면 Planner 가 작업 목록 재구성 | `app/agent/planner_worker.py` | W1~W5, `compare_modes.py` |
| F3022 | RAG 검색 Tool | 2회차 TripPilot 의 ChromaDB(`travel_meta` · `travel_wiki`)를 같은 임베딩으로 검색. 근거 문서와 출처를 함께 제시, 색인이 없으면 `NO_INDEX` | `app/rag.py`, `rag_index.py` | A3 |
| F3023 | 일정 조회 · 등록 Tool | 입출력을 먼저 정하고 로컬(SQLite) 구현체로 확인. `CALENDAR_BACKEND=google` 로 Google Calendar 구현체 교체 (입출력 동일). 조회한 약속을 피해 빈 시간에 일정 배치. 등록 Tool 은 일정 번호 하나만 받음 | `app/calendar_backend.py`, `app/agent/local_tools.py` | A1, A2 |

## 3. 비기능 요구사항 (NF3001 ~ NF3007)

| 번호 | 요구사항 | 구현 · 확인 |
|---|---|---|
| NF3001 | 소스 · 제출물에 API 키 없음 | 키는 `.env` 에서만 읽고 `.gitignore` 로 제외, `.env.example` 은 빈 값. 제출 전 `git grep -i "key="` 로 확인 |
| NF3002 | 화면에 키 · 오류 상세 노출 안 함 | `/api/status` 는 키 '설정 여부'만, Tool 오류 메시지는 키가 든 주소를 넣지 않음, 화면은 사람이 읽을 안내만 |
| NF3003 | Tool 실패가 서비스를 멈추지 않음 | 모든 Tool 이 예외 대신 `fail()`, 실행 흐름은 실패를 기록하고 진행, 응답 LLM 실패 시 대체 문장 (S4, W3) |
| NF3004 | 재계획 무한 반복 없음 | `MAX_REPLAN=3`, 그래프 `recursion_limit` (S3) |
| NF3005 | 처리 시간 | 요청당 LLM 2회(분석 · 응답) + Tool 3~5회. 실제 시간은 `compare_modes.py` 결과(05)로 기록 |
| NF3006 | 프론트 · 백 분리, Agent · Tool 파일 분리 | `frontend/` ↔ `app/`, `tools.py` · `app/agent/*` · `app/logging_agent.py` 분리 |
| NF3007 | 외부 API 출처 · 이용 조건 기록 | `01_도메인_확정.md` 2절, README |
